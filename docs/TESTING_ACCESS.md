# Personal staging access and data persistence

The local staging origin is prepared at `127.0.0.1:8000` and `scripts/start_staging.py` restarts it with secure cookies and test-only access. This loopback address is reachable inside the cloud machine, not from the owner's computer. A usable external HTTPS URL is still blocked by the cloud environment's network policy: tunnel domains return proxy 403 and direct DNS resolution fails. There is no browser-preview tool attached to this environment. The needed tunnel domains were saved to the cloud environment draft; saving a draft does not apply it to this running machine. A named staging host/domain would be a better stable route and needs provider access through environment settings.

The Sayem invitation for the owner-provided email`the owner-provided email` exists only as a one-time private path under `.runtime/sayem-invitation.txt`. No email has been sent and the account is not active until Sayem opens the path, sets a password and enrolls an authenticator. Enrollment automatically adds Sayem to the isolated Test workspace. Sami's address and invitation remain pending; there is no synthetic Sami login for the owner-provided emailthe owner. Sayem can browse sample decisions, create factual records and save new decision drafts. Submitting a fresh decision requires both real operators to be invited; the second signature cannot be supplied by Sayem. The preloaded sample transactions were approved by inaccessible, disabled synthetic identities and are prominently labeled as a test workspace.

A repeatable sample command, `manage.py seed_sample_transactions`, installed 14 clearly synthetic decisions: reported direct funding, test bank funding, mold acceptance, factory purchase, production, goods receipt and quality, supplier bill and simulated payment, order and delivery, management invoice, partial collection, and principal repayment. Synthetic users have unusable passwords and inactive memberships after setup. The command refuses to overwrite existing test work and leaves the live division untouched. No real money or invoice is sent.

Once an external route is available, the practical access steps are:

1. Start `python scripts/start_staging.py` in a retained process from `/workspace/business-dashboard`.
2. Start the reviewed HTTPS tunnel or named staging host pointed only at `127.0.0.1:8000`; verify the public host, TLS and that the live division returns 404 in staging.
3. Give Sayem the staging HTTPS host plus the private one-time invitation path. Complete password and authenticator enrollment. After that, return to the same host `/login/` with the invitation email, password and current authenticator code. Keep the invitation path private and do not put it in public logs or source.
4. In the Test workspace, browse the sample dashboard, inventory, accounting, funding, decisions and reports. Add your own test facts/drafts. New joint approvals wait for the owner-provided emailSami's real invitation and independent login.

A Cloudflare accountless quick tunnel has no uptime or stable address guarantee. If it becomes available, the link works only while both the cloud instance and tunnel process remain running. After a restart, rerun the staging origin and tunnel, get the newly issued URL and use the same login. A stable URL for the owner-provided emailtomorrow requires a named tunnel/domain or another staging host with persistent deployment credentials.

The PostgreSQL data files and private invitations live under ignored `.runtime/`; source lives in the repository. Publishing the prepared cloud environment snapshots its retained filesystem for the owner-provided emaillater tasks, but the publish action is owned by the product and must be completed through environment settings. A full private `pg_dump` backup under `.runtime/` is an additional local recovery copy, not off-site storage. Never use a tenant archive alone to restore passwords, MFA or permissions. Keep the database, backup and source snapshot together. Hosted nightly backup, retention and an external storage destination remain unconfigured.
